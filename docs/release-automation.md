# Android Release Automation

This runbook describes how to build, validate, and publish Petit Android
releases to the Google Play alpha track. Fastlane is the single publishing
implementation. Local operators and the manual GitHub Actions workflow call the
same lanes.

No command in this guide changes `versionCode` or `versionName`. No lane can
select or promote to production.

## Process architecture

```text
Local
  private keystore + keystore.properties
  GOOGLE_PLAY_JSON_KEY=/absolute/private/path/credential.json
                         |
                         v
GitHub Actions        Fastlane Android lanes        Google Play
  alpha environment -> checks and signed AAB  ----> alpha only
  OIDC credential      metadata and changelog
  temporary upload key R8 mapping when generated
```

The workflow prepares credentials and signing files. Fastlane owns release
checks, version and metadata validation, AAB creation, duplicate-version
preflight, and the Play upload.

## What is automated

Fastlane Supply and the Google Play Publishing API can manage:

- AAB upload;
- assignment and release to the alpha track;
- localized release notes;
- localized title, short description, and full description;
- supported icons, graphics, and screenshots;
- R8 mapping upload;
- track promotion in general, although this repository does not automate
  production promotion.

Google Play Console or Google Cloud setup is still required for:

- initial app, API, service account, and Workload Identity Federation setup;
- Play Console app permissions;
- legal terms and agreements;
- Data Safety;
- content rating;
- target audience;
- policy declarations;
- Google review;
- initial tester groups and opt-in configuration;
- protected GitHub Environment settings;
- release intervention after Google Play commits an edit.

The repository contains evidence that Petit release 1 was analyzed by Google
Play. Confirm the app and its current tracks in the authorized Play Console
before the first API operation.

## Repository prerequisites

- Ruby from `.ruby-version`.
- Bundler and the locked gems in `Gemfile.lock`.
- Java 21.
- Android SDK compatible with the project compile and target SDK.
- A private Google Play upload keystore.
- Google Play App Signing enabled for the existing app.
- A distinct upload key, not the Google Play app-signing private key.

Install Ruby with your normal version manager. For example, with `mise`:

```bash
mise install ruby@3.4.10
bundle install
bundle check
```

Do not install Fastlane globally for this repository. Use
`bundle exec fastlane`.

## Local signing setup

Copy the tracked template:

```bash
cp keystore.properties.template keystore.properties
```

Set these properties to the private upload key:

```properties
storeFile=/absolute/private/path/upload-key.jks
storePassword=REPLACE_LOCALLY
keyAlias=REPLACE_LOCALLY
keyPassword=REPLACE_LOCALLY
```

`keystore.properties` and `*.jks` are ignored. Never add either file to Git.
The build lane checks the properties file and referenced keystore before
starting Gradle.

`jarsigner -verify` checks the generated AAB signature. Upload certificates are
commonly self-signed, so a public certificate-chain warning is not a signing
failure. Only an authorized Play API validation or upload proves that Google
Play accepts that upload key for `com.woliveiras.petit`.

## Local Google Play authentication

Create a dedicated Google Cloud service account for Play publishing and grant
it the minimum app-level permissions described below. Keep its JSON credential
outside the repository:

```bash
export GOOGLE_PLAY_JSON_KEY=/absolute/private/path/play-publisher.json
```

The path must be absolute. Fastlane accepts a service-account JSON file locally
and the external-account credential JSON generated by Workload Identity
Federation in GitHub Actions.

Fastlane `2.237.0` is locked in `Gemfile.lock`. Its Supply client explicitly
dispatches `external_account` JSON to Google Auth external-account credentials,
so the credential file emitted by `google-github-actions/auth` is compatible
with the selected version. A static code-path check is not a substitute for the
authorized API validation described below.

Never place the file under this repository, paste its content into a command,
or include it in a support log.

## Initial Google Cloud and Play Console setup

1. Select or create a Google Cloud project dedicated to release automation.
2. Enable the Google Play Android Developer API.
3. Create a dedicated service account. Do not create an Owner or Editor grant.
4. In Google Play Console, invite the service-account email.
5. Grant app-level access only to `com.woliveiras.petit`.
6. Grant only the permissions needed to:
   - view app information;
   - manage the store presence and localized listing;
   - release builds to testing tracks.
7. Do not grant production release, account administration, financial, order,
   subscription, or Play App Signing management permissions.
8. Confirm that the app has an earlier Play build before using Supply. Initial
   app creation and the first manual Play setup are outside Fastlane.
9. Run credential validation before attempting a full alpha edit.

Google Play permission labels can change. Review the effective app-level
permissions in Play Console and confirm that the identity cannot release to
production.

Official setup references:

- [Google Play Developer API setup](https://developers.google.com/android-publisher/getting_started)
- [Fastlane Supply setup](https://docs.fastlane.tools/actions/upload_to_play_store/)

## GitHub Workload Identity Federation

Workload Identity Federation is the normal GitHub authentication mode. It
creates a short-lived external-account credential instead of storing a
long-lived Google key.

Create a Workload Identity Pool and GitHub provider in the release Google Cloud
project. Map at least:

```text
google.subject=assertion.sub
attribute.repository=assertion.repository
attribute.ref=assertion.ref
```

Restrict the provider with a condition equivalent to:

```text
assertion.repository == "petit-app/petit" &&
assertion.sub == "repo:petit-app/petit:environment:alpha" &&
(assertion.ref == "refs/heads/main" || assertion.ref.startsWith("refs/tags/v"))
```

GitHub environments change the token subject format. Inspect a non-production
token claim set during setup and keep the repository, environment, and ref
checks together. Do not trust only the repository owner or organization.

Grant the provider principal only
`roles/iam.workloadIdentityUser` on the dedicated publisher service account.
Do not grant broad project roles to the service account for Play publishing.
Google Play app permissions are configured separately in Play Console.

The workflow uses:

```yaml
permissions:
  contents: read
  id-token: write
```

`id-token: write` exists only on the protected release job.

See the official
[Google authentication action documentation](https://github.com/google-github-actions/auth)
and [GitHub OIDC deployment guidance](https://docs.github.com/en/actions/how-tos/secure-your-work/security-harden-deployments).

## GitHub Environment `alpha`

Create the `alpha` environment in repository settings and configure:

- required reviewers;
- prevention of self-review;
- no administrator bypass where the repository plan supports it;
- deployment branches and tags limited to `main` and `v*`;
- environment variables:
  - `GCP_WORKLOAD_IDENTITY_PROVIDER`;
  - `GCP_PLAY_PUBLISHER_SERVICE_ACCOUNT`;
- environment secrets:
  - `ANDROID_UPLOAD_KEYSTORE_BASE64`;
  - `ANDROID_UPLOAD_STORE_PASSWORD`;
  - `ANDROID_UPLOAD_KEY_ALIAS`;
  - `ANDROID_UPLOAD_KEY_PASSWORD`.

Encode the upload keystore outside GitHub and copy only the encoded value into
the protected secret. Do not save the encoded output in the repository or a
shell-history command that exposes it.

The workflow reconstructs the keystore under the hosted runner's temporary
directory, writes `keystore.properties` with restrictive permissions, and
removes signing and Google credential files in an `always()` step. It does not
upload the AAB, mapping, keystore, properties, or credential JSON as artifacts.

The workflow itself also rejects any ref other than `main` or a `v*` tag. The
GitHub Environment restriction remains necessary because repository settings
protect access before the release job receives secrets.

See [GitHub deployments and environments](https://docs.github.com/en/actions/reference/workflows-and-actions/deployments-and-environments).

## Temporary JSON fallback

If Workload Identity Federation cannot be configured yet, the `alpha`
environment may use:

```text
GOOGLE_PLAY_SERVICE_ACCOUNT_JSON
```

This is less recommended because a service-account key is long-lived and must
be rotated. Configure exactly one authentication mode:

- OIDC variables with no JSON fallback secret; or
- the JSON fallback secret with both OIDC variables removed.

The workflow fails if both or neither mode is configured. Rotate and remove the
JSON key after OIDC is available.

## Canonical Play metadata

All publishable Play listing files live under:

```text
fastlane/metadata/android/
└── pt-BR/
    ├── title.txt
    ├── short_description.txt
    ├── full_description.txt
    ├── changelogs/
    │   └── 2.txt
    └── images/
        ├── icon.png
        ├── featureGraphic.png
        ├── phoneScreenshots/
        ├── sevenInchScreenshots/
        └── tenInchScreenshots/
```

The changelog filename must exactly match `versionCode` in
`app/build.gradle.kts`. Add a new changelog file whenever the version code
changes.

Add other locales as sibling directories with the same required text,
changelog, and image layout. Fastlane validates every locale it finds.

Editable image inputs remain under `docs/store-listing/<locale>/source/`.
Publishable output must not be copied back into `docs/store-listing/`. The
metadata test fails when it finds a second publishable PNG, JPEG, or ZIP there.

Supply replaces image sets on the Play listing. Keep screenshot filenames
ordered and review deletions before deployment.

## Fastlane lanes

List the available lanes:

```bash
bundle exec fastlane lanes
```

Build and verify without Google credentials:

```bash
bundle exec fastlane android build_release
```

Validate the credential only:

```bash
bundle exec fastlane android validate_play_credentials
```

Validate the complete alpha edit without publication:

```bash
bundle exec fastlane android validate_alpha
```

Publish to alpha with status `completed`:

```bash
bundle exec fastlane android deploy_alpha
```

`validate_alpha` uses `validate_only: true`. It contacts the real API but does
not publish and is not proof of tester availability.

Both complete alpha lanes:

1. validate credentials;
2. read the source version;
3. validate signing and metadata;
4. query standard Play tracks for the current version code;
5. run Spotless and unit tests;
6. build and verify the signed AAB;
7. include the R8 mapping when generated;
8. submit the complete edit to `alpha`.

The lane also reports a clear error when Google Play rejects a version code
that was reserved outside the queried track state.

## Manual GitHub Actions deployment

1. Commit or tag the exact source to distribute.
2. Confirm the version-specific changelog is present.
3. Confirm the protected `alpha` environment is configured.
4. Open Actions and select **Release Android Alpha**.
5. Select `main` or the approved `v*` tag.
6. Choose **Run workflow**.
7. Wait for the environment reviewer.
8. Inspect the checks and source provenance summary.

The workflow has no push or pull-request trigger and serializes alpha releases.
An active deployment is not canceled by a later dispatch.

## Version policy

Google Play version codes cannot be reused. Change versions only in a reviewed
source change:

```kotlin
defaultConfig {
  versionCode = 3
  versionName = "1.0.2"
}
```

Then add `fastlane/metadata/android/<locale>/changelogs/3.txt` for every
supported locale. Fastlane never increments or rewrites either value.

## Troubleshooting

### Missing `keystore.properties`

Copy the template and point `storeFile` to the private upload key.

### AAB signature reports a self-signed certificate

An upload certificate is commonly self-signed. The lane requires
`jarsigner -verify` to report a valid JAR signature. Use real Play validation
to confirm that it is the registered upload key.

### Missing current changelog

Create `<versionCode>.txt` under every locale's `changelogs/` directory.

### Version code already used

Inspect all Play tracks and artifacts. Update `versionCode` explicitly, add the
matching localized changelog, review the change, and rebuild. Do not edit a
generated AAB or ask Fastlane to increment the version.

### OIDC authentication fails

Check the provider resource name, service-account email, repository claim,
environment subject, ref condition, `roles/iam.workloadIdentityUser` binding,
API enablement, and Play Console app permissions.

### Credential works but upload is forbidden

Confirm that the service-account email is invited to the correct Play developer
account and has app-level testing-release and store-presence permissions.

### Google auth credential file is missing

Checkout must run before `google-github-actions/auth`. Confirm the workflow uses
the pinned action and `create_credentials_file: true`.

### Tests or Spotless fail

The lane stops before upload. Fix the repository failure and rerun the normal
checks before retrying.

### AAB or mapping is missing

Inspect Gradle release output and R8. The AAB is mandatory. Mapping is uploaded
when R8 generates it and should exist for the current minified release build.

## Interrupting and rolling back

Before the upload step, cancel the local command or GitHub run. The workflow
cleanup step removes temporary files, and GitHub destroys its hosted runner
after the job.

Google Play edits are transactional. A failed edit does not become a tester
release unless Google Play commits it.

After a completed alpha release:

- do not reuse its version code;
- halt or replace the alpha release only through a separately authorized Play
  operation;
- publish a corrective build with a new version code when needed;
- use Play Console as the manual fallback for intervention;
- do not promote or roll back production through this automation.

If a credential may have leaked, cancel the run, revoke or rotate it, inspect
workflow logs and artifacts, and follow the repository security process before
retrying.

## Evidence levels

Report release evidence in separate levels:

1. **Local and static:** Fastlane tests and lanes, workflow lint, Spotless, unit
   tests, metadata, and repository checks.
2. **Signed build:** actual release AAB, source version, signature, upload key,
   and R8 mapping.
3. **API validation without publication:** authorized credential validation and
   `validate_alpha`.
4. **Real alpha deployment:** committed Play edit on alpha.
5. **Tester availability:** approved tester installs or updates the exact
   version through Google Play.

A local build, mock, static workflow test, or validate-only result must not be
reported as a real deployment or tester installation.

## Pre-release operator checklist

- Confirm the source commit or tag.
- Confirm `versionCode` and `versionName`.
- Confirm every locale has the matching changelog.
- Run the local/static checks.
- Build with the private upload key.
- Confirm no credential or signing file is tracked.
- Confirm the service account cannot release to production.
- Confirm the `alpha` environment reviewers and ref restrictions.
- Obtain separate authorization before API validation or publication.
